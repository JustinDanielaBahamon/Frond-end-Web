# Dashboard module refinements for mobile-web coordination

Three dashboard modules received targeted updates to align the web interface with the mobile app's color palette, clarify that device management targets the user's mobile phone rather than the browser environment, and remove unused settings sections. The changes were scoped to assistance (color unification), device (mobile-centric rebranding), and settings (feature removal and accent color expansion).

**Watch for:** Assistance module still uses browser geolocation APIs despite the mobile-centric direction (**confirmed**); device module's service status panel shows hardcoded `enabled: false` for mobile features that should query real state (**confirmed**); settings "Emergencia" card has no interactivity and just tells users to use other modules (**confirmed**).

**Verdict**: NEEDS_CHANGES

## High-level view

The assistance module updated category colors from amber/blue/fuchsia to violet shades, changed the call button from green to violet, and changed the user location pin from indigo to violet. The SOS button stays red.

The device module was rebranded from "Estado del Dispositivo" to "Estado del Dispositivo Móvil" throughout. The permissions panel now shows static "Ver en celular" badges instead of querying browser permission state. The device info panel was replaced with a mobile device panel that checks criticalFeatures for registered devices, FCM token status, last location, and session state. Test buttons were relabeled to reference mobile device data. The hardcoded `#380759` color was replaced with `var(--color-acento)` in button classes. The mobile service entries initialize to `enabled: false` and update asynchronously, causing a brief stale-state flash on page load. The `updateMobileServices()` method calls `updateServiceStatus()` helper that doesn't exist, which will cause a runtime error.

The settings module removed the "Seguridad" card entirely and removed the font size picker from Apariencia. The "Personalización de datos" description now explicitly mentions backend sync. A new "Emergencia" card was added with two static rows that point users to the mobile app and the map module, but neither row is clickable. Six accent colors are now available, including `azulOscuro` (`#130253`), which is extremely dark and may have contrast issues in dark mode.

<summary>Issues (6)</summary>

1. **Assistance geolocation inconsistency** — The module still calls `navigator.geolocation.getCurrentPosition` to populate `miPosicion` and calculate distances, which contradicts the mobile-centric direction. If the web dashboard is meant to display data from the mobile device, the assistance module should fetch the user's last known location from the backend (via PhoneLocationService or similar) instead of querying the browser. Change `usarMiUbicacion()` to fetch from backend, or document that this module intentionally uses browser location for immediate proximity sorting.

2. **Device service status panel shows stale state** — In `loadServices()`, the three mobile-centric entries ("Celular Vinculado", "Token Push Activo", "Última Ubicación Registrada") are hardcoded to `enabled: false` and only updated later by `updateMobileServices()`. If the user refreshes or lands on the page, they'll see three red indicators for a split second until `loadCriticalFeatures()` completes and calls `updateMobileServices()`. Initialize these three entries with a loading state or call `loadCriticalFeatures()` synchronously before setting `services`.

3. **Device test buttons have no mobile integration** — The "Ver Ubicación Móvil" button calls `viewMobileLocation()` which reads `criticalFeatures().lastLocationCaptured` and shows an alert. This is read-only display, not a test. The "Estado Push Móvil" button still calls `requestNotificationPermission()` which queries browser Notification API. The "Notificaciones Móvil" button calls `testNotificationDisplay()` which now just shows a static alert. If these buttons are meant to test mobile device functionality, they need to trigger backend calls (refresh FCM token, request location update from device, etc.). If they're meant to be informational, rename them to "Ver estado..." instead of "Probar...".

4. **Settings Emergencia card is a dead end** — The new "Emergencia" section has two rows: one says "Agrega o edita tus contactos de confianza desde la app móvil" and the other says "Las zonas de riesgo y alertas activas se gestionan desde el módulo Mapa." Neither row is clickable (they're `<div>` not `<button>`), so the card just tells the user to go elsewhere without offering navigation. Either remove this card entirely (the information is redundant with the other modules' existence) or make the rows link to the relevant sections (map module, mobile app deep link if available).

5. **Accent color "azulOscuro" is nearly black** — The new accent color `#130253` is extremely dark (RGB 19, 2, 83) and will have poor contrast on dark backgrounds or when used for text. The existing violet/purple shades are all mid-to-light range; this one is an outlier. Verify this color is intentional and test it in dark mode, or replace it with a lighter shade like `#4c1d95` (purple-900).

6. **Missing updateServiceStatus helper** — `device.ts` calls `this.updateServiceStatus('Celular Vinculado', ...)` in `updateMobileServices()` but the method `updateServiceStatus` is not defined in the component. This will cause a runtime error. Add the missing method: `private updateServiceStatus(name: string, enabled: boolean): void { this.services.update(list => list.map(s => s.name === name ? { ...s, enabled } : s)); }`.

## Color unification in assistance module

The CATEGORIAS map was updated to shift all category colors into the violet/purple/cyan palette. `linea` changed from amber (`#f59e0b`) to violet (`#8b5cf6`), `policia` from purple-600 (`#9333ea`) to violet-600 (`#7c3aed`), `salud` from blue-500 (`#3b82f6`) to cyan-600 (`#0891b2`), and `apoyo` from pink-500 (`#ec4899`) to purple-700 (`#6d28d9`). `bomberos` remains red (`#ef4444`).

The SCSS file received three color updates. The `$call` variable (used for the phone call button) changed from green-600 (`#16a34a`) to violet-600 (`#7c3aed`). The `.as-you` pin marker (representing the user's location on the map) changed its background from indigo-500 (`#6366f1`) to violet-600 (`#7c3aed`) and its box-shadow from `rgba(99, 102, 241, 0.25)` to `rgba(124, 58, 237, 0.25)`.

## Device module rebranded for mobile focus

The component title changed from "Estado del Dispositivo" to "Estado del Dispositivo Móvil" and the subtitle now reads "Diagnóstico de tu celular vinculado" instead of "Diagnóstico completo del sistema."

The permissions panel changed its heading from "Permisos del Navegador" to "Permisos del Celular (App Móvil)" and replaced the note about browser API support with instructions to change permissions in the phone's settings. Each permission card no longer binds its status badge color to the permission state; instead, all three show a neutral gray badge with the text "Ver en celular."

The "Información del Dispositivo" panel was replaced with "Dispositivo Móvil Vinculado." The old panel showed browser, OS, language, timezone, and screen resolution. The new panel queries `criticalFeatures()` and shows registered device count, FCM token status, last location capture timestamp, and session state. If no devices are registered, it displays a message prompting the user to log in via the mobile app.

The "Pruebas de Funcionalidad" section relabeled its buttons. "Probar Geolocalización" became "Ver Ubicación Móvil" and its handler `testGeolocation()` now delegates to `viewMobileLocation()`, which reads the last location from `criticalFeatures` and shows an alert. "Solicitar Permiso" became "Estado Push Móvil" but still calls `requestNotificationPermission()`, which queries browser Notification API. "Mostrar Notificación" became "Notificaciones Móvil" and now shows a static message: "Las notificaciones push se gestionan desde la app móvil en tu celular."

The `loadServices()` method replaced four browser-focused entries with three mobile-centric entries ("Celular Vinculado", "Token Push Activo", "Última Ubicación Registrada") plus the connectivity check. The mobile entries are initialized to `enabled: false` and updated by a new `updateMobileServices()` method, which is called after `fetchCriticalFeatures()` completes. This method calls `this.updateServiceStatus(name, enabled)` for each mobile entry, but the helper `updateServiceStatus` is not defined.

The device.scss file replaced two instances of hardcoded `#380759` with `var(--color-acento)`: `.device-btn--primario` (primary button background) and `.device-action-btn` (floating action button in tests section).

## Settings cleanup and accent expansion

The "Seguridad" card is fully removed. The template no longer renders the card, and the component no longer defines `appLockActive`, `biometricAuth`, or `autoLockTime` signals. All three toggle/link rows (bloqueo de aplicación, autenticación biométrica, tiempo de bloqueo automático) and the blue banner ("Tu seguridad es nuestra prioridad") are gone.

The font size picker is fully removed. The template no longer renders the "Tamaño de letra" section inside the Apariencia card. The component no longer defines the `fontSizes` array or `selectedFontSize` signal, and the `selectFontSize(size: FontSize)` method is deleted. The SCSS file deleted the `.font-size-options`, `.font-size-option`, and `.font-size-option__sample` rulesets. The footer "Tamaño de letra" item was removed.

The "Personalización de datos" row's description changed from "Controla qué información compartes." to "Gestiona qué datos personales se sincronizan con el backend (nombre, teléfono, foto de perfil)."

A new "Emergencia" card was added with two rows. The first row has a `ti-users` icon and reads "Contactos de emergencia: Agrega o edita tus contactos de confianza desde la app móvil." The second row has a `ti-map-pin` icon and reads "Zonas y alertas: Las zonas de riesgo y alertas activas se gestionan desde el módulo Mapa." Both rows use the `.setting-row.setting-row--link` class but are `<div>` elements, not `<button>`, so they are not clickable.

The `accentColors` array expanded from 3 to 6 colors. The original three were `purpura` (`#7c3aed`), `rosa` (`#130253`), and `magenta` (`#710592`). The new array renamed the second entry from `rosa` to `azulOscuro` (keeping `#130253`) and added four more: `rosa` (`#ec4899`), `celeste` (`#0891b2`), and `rojo` (`#ef4444`).
